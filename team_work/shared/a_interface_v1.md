# A 侧接口 v1：已实现部分与接入约束

日期：2026-10-22。本文固定 A 已实现的本地模块和 A1 UDP 格式。它补充 v0，并不表示 B/C 已确认总线、引脚、计时或完整系统。共同接口 v0 中尚未实现的部分继续有效。

## 1. 视频采集与 AI 图像缓存

文件：`rtl/video_a_capture.v`、`ai_frame_mailbox.v`；可见连接示例 `rtl/a_side_units.v`。

默认源 1920×1080，按 x=0,20,…1900、y=0,20,…1060 取样成 96×54。灰度为 unsigned GRAY8；模型量化、精度验证由 C 完成。上下各 21 行黑色填充，CPU 看到连续 9216 字节，行宽/stride=96。填充行读取时生成，不占缓存。

这不是模型训练时预处理的准确率证明。改变采样/裁切方式必须同步 CPU 端验证、文档和测试，不可把运动网格当作模型的原始 96×96 输入。

所有端口目前使用**同一个像素时钟**。C 不能把 CPU 总线直接接入这些端口；须提供带超时的总线适配，以及完整快照/请求-应答跨时钟机制。v1 不分配 MMIO 地址，不猜测 DMA 地址。CPU 驱动适配点见 `firmware/a_side/a_side.h`。

### 来源和提交

- `video_a_capture` 的 VS 高有效，在消隐区上升；每行 DE 高时长为有效宽度。其他极性或非逐行格式需要外部适配。
- `now_ms` 必须是 C 提供且已一致跨域的统一毫秒时间。时间戳采在源帧首个有效像素，帧号从 0 开始、每个 VS 边界递增，uint32 自然回绕。
- 最后一个网格像素延迟到下一 VS，确认物理帧的宽/高后才发 EOF。输出该像素时，元数据仍对应上一帧，不能用当前 VS 新帧的编号/时间覆盖。
- `record_valid` 为一拍；该拍的 `record_frame_id/timestamp_ms/width/height/complete` 描述刚完成的源帧。错误宽度、高度、少行、多行、空帧会标记不完整。
- `source_frames` 是 VS 边界数量；不是完整帧数量，更不是 FPGA 推理次数。
- 必须在摄像头采集源时钟域接入采集统计，才能称“采集帧率”。接在 DDR 读出/HDMI 端只能称显示侧观察值。当前独立仿真不证明实际 MIPI 帧率。

### 所有权/读时序

1. 两个银行状态为 FREE→WRITING→READY→READING→FREE。一次只有一个读者；READY 两帧按完成顺序取。
2. CPU 仅在尚无 lease 时发 `reader_take` 一拍；观察 `reader_active=1` 后读取 `reader_buffer/frame_id/timestamp_ms/checksum`，这些字段保持到下一次成功取得 lease。
3. `read_req=1` 时给字节地址，地址范围 0…9215。请求被采样的上升沿之后，`read_valid=1` 且数据对应该地址，可连续逐拍请求。无 lease、同拍释放或越界返回 `read_error=1`、数据 0。
4. CPU 完整读完后发 `reader_release` 一拍；不要同拍 release/take，不要在 release 后继续使用图像。`a_read_gray96()` 在校验/读取失败时也释放 lease。
5. 忙时丢弃**新到的整帧**，增加 `dropped_frames`，不阻塞视频，也不覆盖 READY/READING 帧。释放与新 SOF 同拍时采用保守策略：当拍原本无 FREE 仍丢帧，下一帧再接收。
6. 不完整 SOF/EOF/abort 取消部分缓存，增加 `malformed_frames`。未写完的 RAM 从不对 CPU 发布；无需复位清空整块 RAM。
7. `checksum` 是对 9216 个 unsigned 字节的 **SUM32**（含零填充），不是网络 CRC32。用于连接一致性检查，不能代替来源与真实画面证明。

参数限制：本接口当前验收配置为 96×54+21+21。内部像素计数/地址 16 位，不能无审查扩大为整幅高清缓存。

## 2. 显示叠加模块

`rtl/video_status_overlay.v` 输入 RGB/HS/VS/DE；输出统一延迟一拍。接入位置应在 DVI 编码前，并同步延迟所有视频控制。原有运动显示额外延迟不变。

- 左上四个状态方块依次为红外、环境、AI、报警；灰色为无效/未报警。两条横条分别为人体分值和融合分值，取值 0…255。
- 文字显示带符号温度、湿度、AI/融合分值、事件类型十六进制码和显示帧号。未接入显示 `-`。温度 centi℃，湿度 centi%RH；湿度超过 10000 自动无效。当前为简易英文缩写与数字字体，`FS` 表示融合分值，不是概率。
- 热图面板独立显示，默认左上 (16,80)，32×24 个热图像素，每点 4×4。热度输入 0…255 由 B 按固定温标归一化，需在报告标注温标，不能将它冒充原始摄氏度。
- `heat_address`/`heat_request` 为当前像素组合读端口；B/C 要提供完整稳定的前台热图缓存，并在 VS 才切换银行。若只有同步 RAM 端口，必须加一拍预取并整体重对齐，不能直接接错拍。A 目前不在像素域接 I2C，也不负责温度校准。
- 无效热图显示棋盘格。标量状态在 VS 锁存，避免中途改变温度/分值造成撕裂。有效期、故障状态和热图银行也应在 VS 一致提交。
- 预测点为 96×54 网格坐标，转换到显示尺寸，显示青色十字；模块**只显示外部预测结果，不计算轨迹**。报警在边缘显示红框，报警保持逻辑由 C 提供。
- AI 和预测坐标只接受 `status_frame_id == display_frame_id`；避免把旧图推理画在当前帧上。C 若推理慢，须提供对应的缓存画面，或者另行设计明确标注帧号/年龄的历史结果面板。不能直接伪造相同帧号。
- 类型枚举：0=无事件，1=人员进入预警，2=数据/设备故障，3=保留。v1 只定义显示/传输码，不表示这些判断已全部实现。不能写成跌倒/姿态检测。

## 3. A1 UDP 网络协议（B 可按此发送）

PC 默认 UDP 39003。状态网页仅绑定 127.0.0.1:39004。字节序：所有多字节字段 **big-endian**。单包总长不超过 1240 字节，载荷≤1200，普通以太网不需要 IP 分片。

| 偏移 | 字节数 | 字段 |
|---|---:|---|
| 0 | 4 | ASCII `T3A1` |
| 4 | 1 | version=1 |
| 5 | 1 | kind：1=事件，2=GRAY8 缩略图 |
| 6 | 1 | flags：0=网络来源待核验，1=PC合成测试；其他值拒收 |
| 7 | 1 | header_size=40 |
| 8 | 4 | session_id，每次板端启动/发送会话必须换值，不能只复用清零的帧号 |
| 12 | 4 | event_id |
| 16 | 4 | source_frame_id |
| 20 | 4 | timestamp_ms（对应来源时间，事件与图像分别保留） |
| 24 | 2 | fragment_index，从 0 开始 |
| 26 | 2 | fragment_count |
| 28 | 4 | total_body_bytes |
| 32 | 4 | body_crc32：完整消息载荷 CRC |
| 36 | 4 | packet_crc32：报头字节 0…35 与本片载荷拼接后的 CRC，不含该字段自身 |
| 40 | ≤1200 | 本片数据 |

CRC 使用标准 IEEE CRC32（多项式反射值 0xEDB88320，初值/最终异或均 0xFFFFFFFF），与 Python `zlib.crc32()` 相同。字段 32 的总载荷 CRC 也受单包 CRC 保护。按 index×1200 定位，除最后一片外必须正好 1200 字节。图像总长 9216，固定 8 片；事件固定 32 字节，1 片。

事件载荷：

| 载荷偏移 | 字段 |
|---|---|
| 0…3 | type:uint8、score:uint8、valid_mask:uint8、alarm:uint8(0/1) |
| 4…5 | temperature_centi:int16 |
| 6…7 | humidity_centi:uint16 |
| 8…11 | visual_age_ms:uint32 |
| 12…15 | thermal_age_ms:uint32 |
| 16…19 | environment_age_ms:uint32 |
| 20…23 | infer_duration_ms:uint32 |
| 24…31 | x0、y0、x1、y1：各 uint16，96×54 网格闭区间的变化框 |

valid_mask 位 0/1/2 为视觉/红外/环境有效，年龄未知用 0xFFFFFFFF，无效值不能参加融合。无运动框时坐标全 0；v1 不单独定义 bbox_valid，因此接收器只将其作为原始诊断字段，不能据此宣称有目标。

接收器按来源 IP/端口、session、kind、event、frame 隔离；允许乱序，忽略相同片重复，冲突片计数，不出半张图；2 秒未齐超时。最多 32 个待重组消息，超限淘汰最老项。完成记录缓存也有界。它没有重传、加密或身份认证；正式验收保留原始包/场景及板端日志，网络收到不自动算“板端已验证”。

Python 参考编码：`tools/a_side/protocol.py`；RISC-V C 编码：`firmware/a_side/a_side.c`。C 编码器已交叉编译，尚未在实际 CPU 或网口运行。发送端要自己按上述布局填写 32 字节事件体，不直接 memcpy C 结构体。
