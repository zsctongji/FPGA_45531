# 第一次实物上板：按关卡操作

适用目录：`D:\FPGA_2026_T3_P3`。记录日期：2026-10-25。

## 先看当前真实状态

- 订单确认：微雪 MLX90640-D55、配套可见光相机、J7 扩展 IO 子卡、DFRobot Fermion SHT30。蜂鸣器具体型号尚未核对。
- 20:24 的 Windows 实测：FT4232 的 A/B/C/D 四路 USB Serial Converter 状态正常；出现 COM13、COM14、COM15、COM16。COM 号可变，四个端口不等于四路都有接线。
- Efinity 的 `ftdi_pgm.bat --list_usb` 实测仍报 `ERROR: No USB target detected, aborting!`。因此当前卡在下载器驱动/访问识别，未下载 FPGA，也没有完成相机实测。
- 五个独立例程已有编译产物；不是已经完成三模态整机。
- CM511 是扩展坞，HDMI 为输出，不能当采集卡接收 FPGA 画面。

## 1. 整理桌面和连接

1. 先关闭板卡电源、断开 USB。板卡放在干燥、绝缘、平整的桌面，清掉散落金属丝，不要放在导电袋或金属板上。
2. 保留厂家配套相机。照片中排线接在 J4；确认插座锁扣压好、排线平直，勿带电拔插。不要按排线蓝面颜色猜接触方向。
3. 红外、SHT30、蜂鸣器先不接。J7 子卡也应断电安装，并对准整个插座，不能错一排。
4. 使用能传数据的 USB 线，电脑 USB → 板卡 Type-C。最好先直连电脑，减少扩展坞供电/接触变量；没有合适接口时可先用现有扩展坞 USB 数据口。
5. 按厂家方式打开板卡电源。亮灯仅表示供电/原有程序运行。

## 2. 先解决下载器识别

按 `Win+X` → **设备管理器**，查看 USB 设备与“端口(COM 和 LPT)”。当前系统已装入 FTDI 串口驱动，但 Efinity 没有列出下载目标，两者不是同一个检查。

本地原理图 `vendor_projects\Ti60_V4\Ti60F225A_V4_SCH.pdf` 的 PDF 第 4 页可见：FT4232 的 **BDBUS0～3 接 JTAG**，CDBUS0～1 接 UART。只有实物与这份 V4 原理图一致时，才按下面的接口操作：

1. 关闭串口助手和 Programmer。
2. 使用 Efinity 官方随附说明所要求的 Zadig（官方来源 https://zadig.akeo.ie/；厂家资料中亦有 2.8 版）。运行后选 **Options → List All Devices**。
3. 核对目标的 USB ID 为 **0403:6011**，接口为 **B / Interface 1 / MI_01**。这是原理图的 JTAG 通道；不是 CM511、不是 USB Composite 父设备、不是接口 C。
4. Efinity 2026.1 的本机帮助 `pgm\doc\topics\task-install-usb-drivers-win.html` 指定 **libusb-win32**；已正确使用 libusbK 的通道无需重复换。只处理已核实的 JTAG 接口 B，保留 C 的 FTDI 串口驱动。
5. 检查选中对象后执行 **Replace Driver**。若看不到明确的 B/Interface 1，或 USB ID 不同，停在此处，不要试选其他设备。
6. 完成后拔插 USB，重新打开 Programmer。接口 B 原来的串口消失可能是驱动切换的正常结果，C 通道的 UART 应保留。

**注意：**资料中 `XL_YLS_DL_Interface_*` 是另一种 FT2232 独立下载器的驱动包，不能只因名称相似就用在本板 FT4232 上。当前我没有替换驱动；上述操作须核对界面中的实际设备后执行。

下载器检查入口：`tools\efinity\2026.1\pgm\bin\ftdi_pgm.bat --list_usb`。命令只列设备，不写 FPGA；命令是否成功看输出，不能仅看批处理退出码。

## 3. 打开 Programmer，下载 LED 临时程序

先核对实际 PCB/芯片与厂家 V4 工程一致，特别是 IO 电压与管脚。芯片同叫 Ti60F225 不足以证明任意例程适用。现有 LED 工程沿用厂家 C4 时序模型，若实物/厂商要求另一速度等级，需要先在匹配工程中重新编译。

1. 资源管理器地址栏输入：`D:\FPGA_2026_T3_P3\tools\efinity\2026.1\bin`。
2. 双击 `efinity_pgm.bat`，打开 Efinity Programmer。
3. 选择 **Local** 目标。在 USB Target 里选择核实的 FT4232 下载器；使用 Generic Board Profile 时应匹配 **Generic Board Profile Using FT4232H**，其 JTAG 接 B 通道。
4. 选择 **JTAG** 模式。此时应能读取 FPGA/JTAG ID。若为空、全 0/全 F 或设备型号不匹配，先停，不点击烧录。
5. 在 Bitstream/Image File 处选择：

   `D:\FPGA_2026_T3_P3\fpga_bitstreams\led\LED_8bit_Test.bit`

6. 点击 **Program FPGA / Start Program**（界面版本的文字略有差异），等待控制台明确成功。失败保留完整日志。
7. 板卡保持通电，观察 8 个 LED；例程会按计数位闪烁，部分频率较快，不必期待固定的“每秒流水”。短按、释放用户按键，比较对应 LED 分组变化。按键 0 还包含 PLL reset 功能，先用其余用户键验证。
8. 拍下下载成功界面与 LED 运行短视频，记录文件名、时间和板卡型号。

这是 **JTAG 临时配置**，掉电会丢失；断电重上后回到 Flash 中的旧程序是正常现象。第一次不要擦写 Flash。不要把 `firmware` 内的 CPU HEX 当 FPGA 配置文件。

## 4. 准备真正的视频显示链路

CM511 的 HDMI 方向是“电脑 → 显示器”。把 FPGA HDMI 接到扩展坞 HDMI，电脑不会收到视频；板卡 USB 也不会自动成为 USB 摄像头。

可选路径：

- 借实验室显示器/电视：**FPGA HDMI OUT → HDMI 线 → 显示器 HDMI IN**，显示器菜单选择对应 HDMI 输入。
- 电脑看画面：**FPGA HDMI OUT → 真正的 HDMI 采集卡 HDMI IN → USB → 电脑**；在 OBS 添加“视频采集设备”，选择该采集卡。CM511 不能替代这张采集卡。

V4 原理图 PDF 第 12、13 页分别显示 **U15 是 HDMI RX 输入，U17 是 HDMI TX 输出**。与照片中的丝印核对后，用 U17；不要只记左右，因为板卡摆放方向会变。实物若不一致，先按实际版本核验。

没有显示器或采集卡时，可以完成 LED 关卡、整理接线和运行电脑自检；暂时不能确认摄像头显示是否正常。无需为了开始 LED 下载立即购买显示设备。

## 5. 按顺序下载三个相机例程

每次在同一个 Programmer 内选 **JTAG + 对应 .bit**，保持板卡通电测试。第一关没有通过，不继续往后叠加问题。

| 顺序 | 完整文件路径 | 现场应看到什么 |
|---|---|---|
| 彩色直通 | `D:\FPGA_2026_T3_P3\fpga_bitstreams\camera_color\ti60f225_oob.bit` | 实时彩色画面；手挥过镜头，画面随动作变化 |
| 灰度 | `D:\FPGA_2026_T3_P3\fpga_bitstreams\camera_preprocess\ti60f225_oob.bit` | 同一现场变为灰度，仍实时更新 |
| 运动 | `D:\FPGA_2026_T3_P3\fpga_bitstreams\camera_motion\ti60f225_oob.bit` | 固定相机，较大物体/手臂移动时灰度画面出现红框；静止后按帧保持结束 |

相机例程使用厂家 1920×1080 配置；显示/采集设备需支持对应信号。运动框是帧差结果，不能称为已经验证的人体 AI。

彩色不出图：先看显示器选的输入、U17/TX、线缆和下载成功日志；再断电检查 J4 排线。MIPI 的 Bank2A/2B 在厂家手册中要求 J2/J3 配成 1.2V；**不要带电移动跳帽，也不要在未核对版本/标号时照猜修改**。不要用电源重启来“保留”刚下载的 JTAG 临时程序；若测试确实需要重新上电，就重新下载 .bit。

每关至少拍 30 秒运行视频，测试时固定相机，先遮挡再移开、挥手、保持静止；记录花屏、撕裂、黑屏、方向和颜色异常。连续运行时间与帧率要实测，不能按参数直接填写。

## 6. J7 子卡与传感器接线——先确定四根线

在彩色相机通路正常后，再关电源、拔 USB，安装匹配的 J7 IO 子卡。若 SHT30 只有焊盘、没有排针，先断电焊好并检查焊桥；不要用杜邦线压在未焊焊盘上临时通电。

对每个 I2C 模块需要辨认 **VCC、GND、SDA、SCL**。常见线色和排针顺序并不统一，不按颜色猜，不直接照抄 Arduino 的 A4/A5 接法。

| 信号 | 接线原则 | 目前能否给出 J7 针号 |
|---|---|---|
| GND | 模块地接主板/子卡已确认的地，共地 | 需核对实际子卡丝印/原理图 |
| VCC | 使用与模块和 FPGA IO 兼容、已确认的电源 | 需核对电源引脚及 IO Bank 电压 |
| SDA | 接最终工程分配的 I2C 数据脚，开漏并有合适上拉 | 当前未固定，不能随意接一个 GPIO |
| SCL | 接最终工程分配的 I2C 时钟脚，开漏并有合适上拉 | 当前未固定，不能随意接一个 GPIO |

DFRobot SEN0330 官方说明支持 2.15～5.5V，带 SDA/SCL/VCC/GND，另有 INT/RST。模块支持 5V 不表示 FPGA GPIO 能承受 5V。整条总线应按已核对的 IO 电压设计，上拉电压同样需要核对。INT/RST 依据实际驱动和原理图处理，首次不要凭空添加接线。

订单能确认模块商品名，但不能确认新到子卡排针方向、版本和引脚定义。继续接线前需要**板卡正面全图、J7 子卡正反面、MLX90640 接口丝印、SHT30 正反面、蜂鸣器正反面**的清晰照片，文字型号也可补充；这些是核对硬件信息，不是重复授权。

## 7. 传感器与蜂鸣器的后续验收顺序

当前这几个独立 .bit 没有整合完整传感器驱动，接上模块不会自动在 HDMI 上显示温湿度和热图。

1. **SHT30 单模块**：接线/管脚配置核对 → I2C ACK → 按实际地址读数 → 温湿度数据 CRC 检查 → 每秒输出带时间戳数据 → 轻轻用手靠近验证温度趋势。不要用火、热风枪或水测试。
2. **MLX90640 单模块**：核对地址/ACK → EEPROM 校准参数 → 两个子帧 → 32×24 温度矩阵 → 坏点处理 → 手掌在镜头前出现热区域。读出原始 RAM 不等于得到校准温度。
3. **两模块同接**：确认地址不冲突、时钟速率和上拉合适，检查长时间无总线卡死，再与可见光时间戳对齐。
4. **蜂鸣器单独验收**：先看实物是三/四针有驱动模块，还是两脚裸蜂鸣器；区分有源/无源和触发电平。裸蜂鸣器不能未经核算直接接 FPGA IO；需要适配驱动。先手动短时触发，再接融合报警请求。
5. 最后由 C 同学将 A 视频接口、B 传感器接口与相同版本的 SoC/APB/固件整合，重新完整编译、检查时序、下载，再做真实三模态闭环。仓库 C 端 APB 已有版本演进，不要将旧固件与新接口混用。

## 8. 三个人现场怎么做

| 人员 | 本轮任务 | 通过依据 |
|---|---|---|
| A（你） | USB/下载器 → LED → 彩色 → 灰度 → 运动红框；固定镜头与显示链路 | 每个 .bit 的下载日志、真实画面录像、异常记录 |
| B | 核对 J7 和模块丝印，逐根记录接线，单独调 SHT30、MLX90640 | 接线表、ACK/CRC、带时间戳真实温度/湿度/热图 |
| C | 保持仓库接口版本一致，准备串口记录/SoC 驱动，再连接三路数据与报警 | 匹配版本、集成编译/时序、真实板上闭环记录 |

今天优先完成“下载器可识别 + LED 正常”两个目标；解决后再进入相机显示。不要三个人同时换线和换程序，现场只指定一人操作板卡电源和接线。

## 常见现象与第一步检查

| 现象 | 第一步 |
|---|---|
| 全不亮 | 关电源，查供电线、USB口和主板开关 |
| Windows 有 COM，Efinity 无目标 | 核对 FT4232 JTAG 接口 B 的 libusb 驱动，不随机试 COM 口 |
| 有下载器，JTAG ID 异常 | 核对板卡供电、目标 profile、B 通道和型号，保留控制台日志 |
| 下载成功但断电恢复旧程序 | JTAG 临时配置正常现象；重新下载，不先擦 Flash |
| 无 HDMI 信号 | 确认是 U17/TX、真正显示输入、正确输入源，不是 CM511 输出口 |
| 运动框覆盖全屏 | 固定相机，稳定光线；帧差也会响应整幅晃动和曝光变化 |
| PC 页面有 SYNTHETIC/127.0.0.1 | 这是电脑测试数据，不能作为 FPGA 实测证据 |
