## 复现

在具有原C工具链、Icarus、MSVC和既有桌面模型依赖的工程根目录运行：

```powershell
python -X utf8 tools/replay_team_real_data.py --a-archive "实际路径/A_video_source_20261029.zip" --b-archive "实际路径/B_thermal_dataset_20261030.zip" --repo "实际路径/FPGA_cooperation_handoff"
```

本机默认归档缓存为`build/team_real_20261031/`，可直接运行`21_replay_real_team_data.cmd`。`--repo`提供共享仓库内原始`b_sensors.h`和`b_thermal.c`；B4三组C/H由已校验的B归档选取到build。工具不执行包内脚本，不整体解压、不覆盖现有RTL，不读取串口。归档改变或样图/数据清单校验失败时直接拒绝；报告与生成物应在接收机器上重建。

5张图的`cpu.gray`是从实际仿真CPU AXI返回beat保存；`ddr.gray`为DDR模型内存核对。每张图在独立目录运行，不覆盖原合成自检图或697项检查使用的报告。输入在网格层送入，因此不声称本次覆盖物理CSI解包或重新验证1920×1080源采样；原49次RTL报告保持独立。

## 必须保留的验收范围

A图像来自**显示域**采样：`source_frame_id=null`、本地148.5MHz显示时钟、`shared_soc_time=false`。回放使用测试台的合成帧号/公共时间进行C2协议测试，原始显示帧号/时间单独保留，未把显示时间改名成真实源首DE时间。运动字段由重放序列重新产生，不声称复现原现场同帧运动结果。

B数据来自另一独立诊断会话。其时间是`BQFAST01`板端诊断时钟，年龄起点是观察到首个ready，不是曝光时间，且不包含后续CPU换算/融合。没有把A/B拼成真实同步样本或网络事件。100条是重放原有采集，没有新增100次上板测量；本轮也未重新执行原厂温度算法，算法重算依据仍是B原报告，本轮核对其输出文件哈希和当前C ABI/策略行为。

模型仍采用既有桌面元数据兼容版本，原板端模型未改。本次只验证传输与预处理一致，没有人体/跌倒准确率、板端TFLM数值一致性或整机实时性结论。

## 下一步工程接入顺序

1. **真实C3外设。** 当前厂家`soc.h`没有可直接使用的I2C/GPIO外设映射，不能凭空填写地址。需在当前SoC/APB增加或接入实际控制器及引脚，绑定已存在的C2/C3公共时间；核对开漏、SCL/SDA、B5静音、事务超时与总线释放，再实现`c3_hal_t`回调。B的独立UART诊断后端不能直接作为最终CPU后端。
2. **确定热图发布策略。** 现有严格取样与B4带掩码策略是两条不同路径。本轮没有将后者接进实时固件，也没有把3/64伪装为7/0。建议最终流程显式选择受控的坏点掩码策略，保留原flags/errors和质量状态，禁止把620号占位0当测得温度；随后测量最终程序内的完整500ms期限。
3. **真实相机到CPU。** 合入A实际CSI/显示连接，在最终C2布局中传递真实源帧ID和首DE公共时间，使用实际软核取得完整图像及推理日志；先做BRAM资源优化，再复验完整物理视频/双像素适配与P&R。
4. **联合验收。** 同一最终镜像下同步验证A/B数据方向、AI/融合、报警与网络事件；图像、热图和通知必须来自同一实际会话。A/B已有独立长稳记录不替代这一项。
