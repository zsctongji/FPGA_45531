## 六、必须共同提前解决的两个接口

**第二：三路数据与事件接口。** 第一天下午先定字段、单位、有效标志和帧握手，再并行写代码。初稿位于 `team_work/shared/interface_contract_v0.md`，标为 v0 的方案尚未实现。最终地址、寄存器和时钟连接由 A/B/C 评审后 C 固定，不能由三个人分别起名、分别定义单位。

## 九、只有一块板时怎么并行

- 一台电脑保留 `D:\FPGA_2026_T3_P3` 为主集成目录。三人各自使用工作副本，五个已验证工程留作回退。C 负责合入最终整机；每个人负责自己的修改说明和验收结果。
- 白天分三段预约板卡，例如 A 09:00～11:00、B 14:00～16:00、C 19:00～21:00；这些是可调整的用板时间，不是三个人全天只能做两小时。其余时间分别做代码、仿真、回放、PC 工具和文档。
- 每晚安排一次三人联合联调。用板者完成后交出实际固件版本、接线照片、串口日志和下一步，不只说“可以了”。
- 对接问题卡住约一小时就向接口负责人同步，附完整错误和复现步骤；不各自改同一份顶层/外围文件。接口改变后立即更新版本。
- 每人每天交一份简报：完成了什么、证据在哪里、卡在哪、需要谁在何时提供哪个接口、明天交什么。模板已放在 shared 目录。

## 十、最终验收与材料分工

1. 三人一起做“无人、人员进入、静止、离开、普通物体运动、热源干扰、传感器断线、解除/重新布防”等场景；保留原始记录。测试次数、重复事件、漏报、误报和恢复时间都如实统计，不把小规模演示写成通用准确率。
2. 实际视频采集帧率、AI 推理速率、推理延迟、端到端报警延迟分别测量；安排不少于 30 分钟的连续运行测试作为团队内部最低验收目标，最终稳定性测试可继续延长。
3. A 写视频/显示/输入帧率部分并提供演示素材；B 写传感器/校准/报警/网络部分并汇总排版；C 写软核/AI/总线/预测/资源时序并制作发布包。每个人对自己写的指标负责，三人共同检查报告、PPT 和录像。
4. C 的发布包必须能说明 FPGA 配置、CPU 固件和 Flash 布局的对应关系；不能把 CPU HEX 当作 FPGA HEX。A/B 按说明在实物上复现一次，留下复现记录。
