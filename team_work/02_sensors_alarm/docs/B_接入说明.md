集成时把 B 的 include/src 添加到 C 的既有固件构建，复用团队已有 c3_hal.h、c3_hal.c、cooperation_v1.h。upstream_snapshot 仅供本地回归对照，不能作为第二套 ABI 合入团队工程。编译官方 MLX90640_API.c 并链接数学库，切勿同时链接其他实现的同名 I2C 钩子。驱动由一个任务串行调用；没有 ISR/多线程同步保护。

## 典型调用顺序

1. C 将 HAL now_ms 接到整机公共 APB 时间源（c3_shared_time_bind / c3_shared_now_ms），并定义读时钟失败的处理策略；CLINT / c3_bind_sapphire_time 仅供独立 C1 诊断，不能替代整机统一时间。C 还需提供可超时并恢复 STOP/总线状态的 I2C 后端，以及逻辑 GPIO 后端。地址是 7 位；总线 0、GPIO 0/1 还不是物理引脚编号。
2. SHT30 初始化后调用 start，主循环调用 poll；EBUSY 继续调度其他任务，OK 才取样。每个新周期立即清除旧有效标志。get 会检查 2000ms 年龄，不接受未来时间；0ms 是合法时间值。上电稳定、状态检查、软复位和总线配置按实际模块手册处理，当前没有替硬件猜测初始化寄存器。
3. MLX 会话 begin(hal,预算ms,最大事务数)，调用官方 EEPROM/控制或采集接口，检查官方返回码，再检查 session_end；任一失败必须调用 thermal_fault，禁止继续使用上轮有效温度。不能把 GetFrameData 返回的 0 误当作唯一成功值：0、1 分别是合法子帧。不能绕过会话直接调用官方 I2C 接口。
4. 真实设备 EEPROM 提取参数并校验，CalculateTo 计算每个子帧；转换后立即 push(subpage,chess,celsius,bad_bits,1)。bad_bits 中 1 表示已知坏点；输出 pixel_valid_bits 中 1 表示可用点，两者含义相反。两页收齐前返回 EBUSY。
5. C 的已确认事件触发 alarm_request(1)，主循环定期 poll；解除调用 request(0)。重复请求不会延长持续上限。故障/时间上限后需先解除再重新使能。上限只是软件策略，调度停止或 GPIO 后端故障时，软件无法保证实物关断。

## 明确未完成的热成像部分

当前交付是 I2C 适配与“校准后”热图组装，不是已经完成实物标定的完整 MLX90640 采集服务。真实 EEPROM、完整参数抽取/物理温度换算、原始帧读出期间的数据一致性检查、坏点处理策略、刷新率与采集调度均需接线后联调。官方源码保持原样，其采集函数含等待 ready 的循环；本适配以会话时间和事务次数限制 I2C 等待，但不能中断一个不返回的 HAL 回调，也不是校准算法的 CPU 看门狗。

当前质量策略保守：任何不可用像素都会清除整帧 QUALITY 并设置 PIXEL_QUALITY，保留有效位图供诊断；待 C 确认其是否允许排除已知坏点后继续融合。没有把坏点补成正常体温。

## 时间与内存

- 统一 uint32_t ms，使用无符号差处理回绕；每次调度/预算/年龄比较间隔必须小于 2^31 ms。
- SHT 时间戳是本任务验证完整读数的时刻，单次转换有 16ms 等待；精确传感器曝光时刻及链路延迟需实测。
- 热图时间戳保守使用两页中较早的组装时刻，防止第二页给旧数据续期；获取原始帧到转换完成的延迟仍需计入上板时序评估。这不是已验证的硬件级时间对齐。
- 所有接口只在 valid_flags == 7 且 error_bits == 0 时提供有效样本；调用者同时检查 get 返回值。无效值即使数值为 0 也不能当作正常观测。
- b_thermal_pair_t 包含双缓冲和位图，另有官方参数、832 字 EEPROM、834 字原始帧、768 浮点温度内存；正式固件必须检查链接映射与栈，建议静态分配。
