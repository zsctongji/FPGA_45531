# 三人接口约定 v0（待评审、尚未实现）

2026-10-24 更新：C 已发布 interface_contract_v1.md 及 C/C++ 头文件，固定软件数据/握手/API 边界。物理地址、DDR/CDC 和实际引脚仍待共同验证；v1 不表示 A/B 已评审。本文保留为历史草案。

2026-10-22。本文定义拟交付的数据与责任，不表示这些接口已经存在于 FPGA/CPU 工程。A/B/C 第一轮评审后由 C 发布 v1；具体内存地址、寄存器、总线端口和时钟连接须经过实际设计与验证，本文不猜测这些值。

## 1. 数据流及责任

| 数据方向 | 生产方 | 消费方 | 生产方负责 |
|---|---|---|---|
| 视频、抽样图、运动统计 | A | C、显示及网络模块 | 帧完整性、像素格式、帧号、采集时间、缓存写入 |
| 温度阵列、环境量及状态 | B | C、A | 校准/换算、质量、采样时间、错误状态 |
| AI、融合事件、预测点 | C | A、B | 模型预处理、决策、事件编号与时间、有效性 |
| 事件及缩略图网包 | B，C 协助 SoC 接入 | A 的 PC | 板端协议、缓存读取、分包和发送 |
| PC 接收及落盘 | A | 全体 | 解包、超时、乱序/丢包识别、原始记录 |

## 2. 统一时间及无效状态

- 使用一份单调递增 `uint32` 毫秒计数。C 定义来源和分发方式；不把三个模块各自启动的计数器当作同一时钟。
- 视频时间定义为源帧首个有效像素时刻；传感器时间定义为完整采样形成的时刻。CPU 读取数据的时间另记，不能覆盖采集时间。
- 多位时间戳/图像/数组跨时钟使用快照握手、双时钟 FIFO 或经过验证的缓存机制；不能逐位同步多位计数或逐位同步整个图像。
- 年月日/实际布防时段与运行毫秒计数分开。第一个演示先使用明确的手动布防，不假装拥有尚未校时的 RTC。
- 完整、已校准/换算、未过期三个条件分别记录。无效值不能用零填充冒充正常。
- 当前独立融合模块的默认最大年龄：视觉 1000 ms、红外 500 ms、环境 2000 ms；这些是可调整初值。未来、过期和缺失样本应被拒绝，不能把上一事件直接当作新证据。已触发报警可按既定保持时间到期，不因数据停更而无限刷新。
- v1 必须固定对齐参考点和允许时间差。若以视频帧首时刻为基准，要保存足以匹配该时刻的传感器历史样本；CPU 读到的最新样本可能晚于该帧，不能无条件拿它替换对应快照。

## 3. 视频/AI 输入

| 字段 | 类型/单位 | 说明 |
|---|---|---|
| `frame_id` | uint32 | 每个源视频帧递增；CPU 处理可抽帧，编号不能重新从 0 伪装连续 |
| `frame_timestamp_ms` | uint32/ms | 视频采集时间 |
| `image_valid` | bool | 完整图已写入且可读 |
| `image_width/height` | uint16 | AI 候选输入为 96×96；不是当前运动网格尺寸 |
| `image_format` | enum | 初版约定 GRAY8：0～255、逐行、从左到右、从上到下 |
| `buffer_id/address/stride` | v1 确定 | 地址/存储方式由 A/C 按资源和带宽决定，不在 v0 硬编码 |
| `image_checksum` | uint32 | 数据一致性调试用，算法由 A/C 统一；需配帧号、时间及实际画面一起证明数据来源 |
| `motion_valid` | bool | 有完整上一帧可比较；首帧和坏帧恢复时不能当作有效静止 |
| `motion_count` | uint32 | 96×54 网格中达到阈值的变化点数 |
| `motion_bbox_valid` | bool | 是否存在变化区域 |
| `motion_x0/y0/x1/y1` | uint16/网格坐标 | 运动网格原点在左上，x 为 0～95、y 为 0～53；闭区间 |

建议先验证全帧缩放/采样到 96×54，再上下各补 21 行形成 96×96。此方案尚未做真实模型准确率验证；C 须与厂商输入处理及保留测试样本比较，必要时和 A 一起改变方案并升级版本。

A 交灰度 0～255；C 负责按实际模型/厂商流程转换到模型张量。不能混淆 unsigned 灰度与 INT8，也不能在未核对模型时仅凭经验固定量化公式。当前静态例程的原始样图已有自己的预处理方式。

缓存建议采用至少两个独立可识别缓冲区和明确所有权：`FREE → WRITING → READY → READING → FREE`。A 不覆盖 CPU 正在读的图；C 只读已经提交的完整图，结束后释放。忙时按约定丢弃新帧或旧待处理帧并增加计数，不阻塞持续视频。视频时钟与 CPU 时钟不同，具体握手和存储实现由 A/C 验证。

## 4. 红外与环境输入

| 字段 | 类型/单位 | 说明 |
|---|---|---|
| `thermal_id/timestamp_ms` | uint32 | 一张完整温度图的编号和形成时间 |
| `thermal_valid` | bool | 完整且通过实际型号要求的温度换算和质量检查 |
| `thermal_temperature[24][32]` | int16/0.01℃ | 若采用 MLX90640，则为 768 点；按实际方向归一化为上到下/左到右 |
| `thermal_error` | enum/位标志 | I2C 超时、校准错误、子帧缺失、质量不合格等 |
| `environment_id/timestamp_ms` | uint32 | 环境完整样本编号/时间 |
| `temperature_centi_c` | int16/0.01℃ | 例如 2534 表示 25.34℃ |
| `humidity_centi_percent` | uint16/0.01%RH | 例如 5678 表示 56.78%RH；有效范围 0～10000 |
| `environment_valid/error` | bool/enum | 完整性、CRC、换算及通讯错误 |

B 先交真实原始/补偿后采样日志，之后才定过滤和场景阈值。不可恢复的坏点以约定标志/掩码表示，不能参与极值或热特征计算。B/A 固定传感器安装方向，先把热图独立显示，并记录与可见光位置的对照。

环境量怎样用于背景补偿或场景阈值，由 B/C 用数据写清楚。原始摄氏度、湿度不能直接冒充 0～255 证据分值；“传感器在线”也不能直接当作“检测到人员”。

## 5. AI、融合事件与预测输出

| 字段 | 说明 |
|---|---|
| `ai_frame_id/ai_valid` | 对应真实输入视频帧及推理有效性 |
| `person_score` | 按实际模型定义导出的分值；输出张量类型、量化参数、阈值另记 |
| `infer_start_ms/end_ms` | 实际推理起止时间；不代替输入采集时间 |
| `event_id` | 新事件递增；持续同一事件不逐帧创造新编号 |
| `event_type` | v1 枚举；初版场景人员进入预警，不能标成已实现跌倒/姿态 |
| `event_timestamp_ms/source_frame_id` | 触发事件时间及对应图像帧号 |
| `fused_score` | 0～255 融合分值；可以显示为分值或归一化百分数，但不能宣称已校准概率 |
| `data_valid_mask/ages` | 三路有效性和年龄，便于判断过期或来源不齐 |
| `alarm_active/acknowledge/armed` | 保持、解除和布防状态 |
| `prediction_valid/x/y/horizon_ms` | 单目标预测点、坐标系和未来时长；不得越界而不处理 |

运动包围框不自动等于人体框。轨迹预测需注明跟踪对象、坐标系、时间跨度、速度计算和误差；全图人体分类的能力不应被写成多目标检测。

## 6. 以太网事件上报初稿

- A/B 第一轮先统一 PC 的 IP/端口、消息格式和测试工具，C 负责需要的 SoC 接入。参数可配置，不擅自改用户现有网络设置。
- 事件至少含事件编号、时间、类型、位置/坐标系、分值、环境量和对应缩略图编号；缩略图可先使用真实 GRAY8 图，不额外引入非本题硬性要求的图像压缩格式。
- 96×96 灰图为 9216 字节，不能假定它能放进一个普通以太网帧。初版可按每片有效图像数据不超过 1200 字节分包；各片带事件/帧号、片序号/总数及校验信息。A 只显示重组完整的图，缺片和超时明确标记。
- PC 自发数据用于开发和丢包测试；验收必须由真实板卡经实际以太网发出，并能对应到实际场景。
