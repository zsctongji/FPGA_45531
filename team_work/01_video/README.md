# A：视频、显示与 PC 接收

A 为此前完成准备和采购的同学。后续不承担全部驱动、集成和材料编写；主责任为下列视频链路。

## 从哪里开始

- 现有 `projects/02_camera`、`04_camera_preprocess`、`05_camera_motion`。
- `docs/video_display_preprocess.md`、`docs/motion_fusion.md`。
- `rtl/video_grid_sampler.v`、`frame_motion_stats.v`、`video_motion_display.v`。
- 已有 04/06/10 三个 cmd 分别编译彩色、灰度和运动显示；它们不执行上板下载。

## 按顺序交付

1. 核对 B 给出的实际板型和摄像头，做真实彩色/灰度/运动显示对照，保存启动步骤和实物录像。
2. 用输入视频帧计数实测采集分辨率、帧率、丢帧；写明观察时长，不能用显示刷新率替代采集帧率。
3. 输出 96×54 灰度和运动统计；按共同接口给 C 提供 96×96 AI 输入、帧号、采集时间和校验值。运动框只表示变化区域。
4. 与 C 共同完成视频 DMA/缓存和 CPU 访问。两个人先验证帧握手和数据一致性，再接入复杂显示。
5. 接 B 的热图/温湿度和 C 的事件，显示视频、热图、环境、状态、事件类型/分值、报警红框和预测点。
6. 提供 PC UDP 接收工具，保存真实板端事件和缩略图，和 B 一起验收网络扩展。
7. 完成本人章节、帧率/显示测试记录与演示素材；配合三人共同场景和连续运行测试。

## 需要队友提供

- B：确切型号/接线、完整温度图与温湿度、有效标志/时间、板端网络报文。
- C：统一计时、缓存/寄存器协议、模型输入要求、AI 结果、融合事件、预测点。

## 交给队友的成果

视频侧源代码与版本、原始/灰度缩略图、帧数据校验、运动数据、输入帧率 CSV、PC 接收工具、实物录像和文档。遇到总线/DDR 问题与 C 联合处理；不在两个工作副本里分别定义地址和握手。
