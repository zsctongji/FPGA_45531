## 已固定的软件边界

- ABI_VERSION = 0x00010000；共享描述符固定 64 字节，16 个 uint32，全部小端；不在 ABI 中使用指针、bool 或编译器 enum。
- 图像：96×96，GRAY8，stride=96，9216 字节，逐行从左上开始。96×54 网格上/下各补 21 行、填充0是联调候选方案；2026-10-24桌面回放已观察到people2样图由有人翻为无人，不能视为质量验收通过。接口也允许A直接交96×96图；最终摄像头缩放/裁剪策略须A/C用真实样本确认，并在日志注明策略版本。保留源帧号，源帧号允许跳号。
- C1 的原厂两张 TFLM 样图已经预归一化，逐字节原样送入 int8；其余四张原始灰度使用 pixel-128。实时图像先采用后一路径，但输入分布、补边影响须用样图和真实数据验证。换模型须重审，不把此公式推广到任意 INT8 模型。
- 图像校验使用 FNV-1a 32：初值 2166136261，逐字节 XOR 后乘 16777619，uint32 回绕。A 的校验覆盖提交的完整 GRAY8 9216 字节；C 另记模型张量校验，二者不可混用。此校验仅用于调试，不是安全散列。
- 运动坐标始终是 96×54 网格、闭区间；仅在上述补边方案下，映射到AI图像时y加21。选择其他裁剪/缩放策略时须重新定义映射，不能套用该偏移。运动框不等于人体检测框。
- 温度图按 MLX90640 候选格式为 768 个 int16、单位 0.01℃，另有 96 字节有效像素位图。若最终器件不同，需版本升级。
- 环境温度 int32/0.01℃；湿度 uint32/0.01%RH，范围 0..10000；有效性和 error_bits 独立保存。传感器接口失败不得发布 valid 样本。
- 传感器 valid_flags 单独定义为 COMPLETE=1、CONVERTED=2、QUALITY=4，三者齐全且 error_bits=0 才整体有效；与图像的 MOTION/BBOX 位语义不同。像素有效位图按像素序号 i 的第 i/8 字节、LSB 位 i%8；坏点不能参与统计。错误位为超时1、NACK2、CRC4、校准8、子帧16、总线32、像素质量64。
- COMPLETE=1，MOTION=2，BBOX=4；没有完整上一帧时不置 MOTION。BBOX 置位须同时置 MOTION，并满足边界检查。

## C2 缓冲交接

采用两个槽位，控制服务唯一修改所有权：
FREE → WRITING → READY → READING → FREE。
写帧失败允许 WRITING → FREE。没有空闲槽时丢弃新 AI 候选帧，累计 dropped_new_frames，视频采集/显示仍持续。
READY 不自动覆盖；CPU 需要持续取走并释放槽，不能长期保留两帧。

每次开始写入，generation 加一。ACQUIRE 和 RELEASE 均带 buffer_id+generation；旧 generation、错误状态和重复释放返回 ESTATE。generation 为 uint32；系统不允许命令跨越 2^32 次同槽复用仍留在队列。复位清空全部握手/命令及 CPU 本地旧句柄，禁止复位前句柄继续使用。

控制服务须串行执行命令；C 参考 C 实现不含原子指令、锁、缓存维护或 CDC，不允许 A/CPU 各自直接修改 state。最终硬件将写完成、CPU 取帧和释放转为握手命令。需要更低延迟时再评估第三槽，须升级配置。

### 相对内存布局（固定相对偏移，未指定物理基址）

| 区间/偏移 | 用途 |
|---|---|
| 0x0000..0x0fff | 控制/描述符/传感器快照预留，具体槽表由最终实现发布 |
| 0x1000..0x33ff | image slot 0，9216 字节 |
| 0x4000..0x63ff | image slot 1，9216 字节 |
| 0x7000..0x7fff | 温度图与环境快照预留 |
| 0x8000..0xffff | 扩展与对齐余量 |

data_offset 仅允许 0x1000/0x4000；不由 A 传任意 CPU 地址。物理基址必须在实际 DDR 容量、CPU linker、视频帧缓存和 DMA 地址映射共同验证后填写。当前程序不对这些偏移做 MMIO 访问。

## 唯一 DDR 控制体系及实施门槛

2026-10-24 C2 更新：`projects/06_soc_c2` 已实现可移植RTL及厂家SoC接入副本，详见 `../03_ai_soc/C2_VENDOR_APB_CACHE.md`。控制服务独占槽状态，CPU经APB传输ABI v2执行QUERY/ACQUIRE/RELEASE；图像ABI仍是本v1，没有把状态镜像到DDR控制页。APB/ID适配和RX只读缓存后端已有离线验证；候选内存图、物理SoC/视频接入及板上缓存仍待确认，以下物理验证门槛继续适用。

以 projects/03_tinyml 的 SoC/DDR 系统为候选整机基础。其顶层已包含一个 ddr3_top 和 S_COUNT=3 的 AXI 互连；CPU 和 TinyML 已占用接口，不能把 camera 顶层的第二套 DDR 控制器并联上板。
A/C 下一步把视频写读、缩略图写入整合到同一 AXI/DDR 体系，确认空闲端口实际状态或扩展仲裁。AXI 宽度、地址偏移/重映射、burst、ID、响应与复位全部逐项对照，不能只连地址/数据。

CPU BSP 的 DDR 地址窗口很大，linker 的 128 MiB 只是当前链接配置，并非实际器件容量证明。64 字节 D-cache line 已启用，volatile 和 fence 不能代替 DMA 缓存一致性。集成必须选择并验证：
1. 把共享区配置为确实不缓存，并从 linker 排除；或
2. 使用现有核支持的 cache clean/invalidate，在所有权转换处执行并证明范围/对齐正确。
在策略未证明前，不允许 CPU 和 DMA 共读写上述物理区。

视频 RGB888 按 1920×1080×30 每方向最低约 186.6 MB/s，视频 DDR 写+显示读至少约 373.2 MB/s；若存 RGB565 则至少约 248.8 MB/s。以上未含消隐、burst 效率、仲裁和 AI 权重访问。A 须确认实际格式和帧率，C 重新计算吞吐和最大等待。AI 输入图本身 9216 字节/帧不是整机带宽。

DDR/CDC 实测门槛：CPU 写入/读取保留测试区、视频并发读写时校验不变、图像槽校验一致、延迟消费者时不覆盖读取槽、反压与复位恢复、实际资源/时序与长稳日志。主机参考测试不替代这些证据。

## 时间源与对齐

软件统一 uint32 毫秒、周期约 49.7 天；所有超时和比较窗口 < 2^31 ms。age_valid(ref,sample,max) 用无符号差，拒绝未来/过期样本，支持自然回绕。
C1 独立工程实际用 CLINT 100 MHz → /100000，已通过 BSP 绑定交叉编译。它不是已经分发给视频/传感器的整机时间。
最终集成统一的时间模块在 100 MHz 外围域产生单一毫秒计数，CPU 和 A/B 必须读该同一计数。若采用 CLINT，需从该实际计数导出；若改用公共 APB 定时器，则 C3 只替换 now_ms 后端。禁止各自启动相同频率计数器冒充同一时间。
2026-10-25实现使用公共APB计数器，经已有请求/确认mailbox传递稳定的完整32位快照，替换未实施的Gray提案；传播延迟纳入预算。CPU/C3直接读取同一计数，禁止逐位同步自由变化的二进制总线。RTL三组异步时钟/回绕/复位及A桥传递测试通过，物理CDC和频率仍待验收。
2026-10-25源像素接入：native已接A的video_a_capture，使用统一视频时间在源GRAY8接口首个有效DE像素锁存；该时间随网格、延迟EOF、A缓存和DDR描述符保留，不在网格SOF或下一VS覆盖。实际MIPI/灰度前端的流水延迟和相机VS到首DE偏差仍需实测。环境/热图timestamp是完整有效样本形成时刻，CPU收取时间另记。

初版以图像时间匹配不晚于图像的传感器历史：红外最大差 500 ms，环境最大差 2000 ms；结果发布时图像最大年龄 1000 ms。这些是工程初值，需真实数据调优。历史缓冲必须保留足够数据；不能以未来的最新样本代替历史匹配。

## C3 对 B 的可调用 API

- 整机使用c3_shared_time_bind(clock,io)及c3_shared_now_ms(clock,&ms)，校验APB v2.2/时间能力/频率，失败保留输出并返回错误；0是合法时间。见 ../03_ai_soc/TIME_AND_C24_ACCEPTANCE.md。
- c3_now_ms(hal,&ms)及CLINT后端保留给C1独立诊断；不要与整机公共时间混用。
- c3_i2c_write_read(hal,bus,address7,tx,nt,rx,nr,timeout_ms)：7-bit 地址，不含 R/W bit；写后重复 START 再读，最后 STOP；支持只读/只写。超时必须非零且 <2^31 ms。
- 初版传感器逻辑总线固定 C3_I2C_SENSOR_BUS=0；它不等于任何已接线的I2C实例，实际设备地址由B核实型号后配置。
- 返回 OK=0，EINVAL=-1，EBUSY=-2，ESTATE=-3，ENOTSUP=-4，ETIMEOUT=-5，ENACK=-6，EIO=-7。
- I2C 后端负责整个调用的有限超时、ACK 检查和失败后的 STOP/总线恢复；当前封装只校验参数并传递后端状态，不声称它能中断一个卡死的后端。
- CRC、EEPROM/校准、子帧、坏点、重试和数值换算由 B 的器件驱动负责。RX 仅在 OK 后可使用；失败时内容未定义且不能发布有效样本。
- c3_gpio_write：逻辑通道 0=报警 LED，1=蜂鸣器使能；active=0/1。后端负责物理引脚、电平极性及有源/无源蜂鸣器的 PWM 策略。
- c3_capabilities 明确可用功能。当前 c3_bind_sapphire_time 仅 TIME=1；I2C/GPIO 返回 ENOTSUP。B 可在 PC 用测试后端开始驱动开发，不能把 mock 数据作为实测。
