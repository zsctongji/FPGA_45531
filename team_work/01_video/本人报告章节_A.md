# 视频采集、图像缓存、显示和 PC 接收子系统

## 设计目标和当前状态

本子系统为多模态人员进入预警提供图像输入、采集质量记录和结果显示，并通过 PC 工具接收事件及图像。现阶段完成了可移植 RTL、PC 程序和协议实现，进行了独立综合与仿真。摄像头、真实 CPU/传感器、板端网口和整机尚未完成联调；以下软件测试数据不能替代实测数据。

## 图像流和缓存设计

现有厂商相机/DDR/HDMI 工程作为基础，保留独立彩色、灰度和帧差显示版本。新增采集接口在逐行有效像素流上按 20×20 间隔取样，将 1920×1080 视频生成 96×54 灰度网格。首个有效像素的统一毫秒时间和逐帧编号随图像保存；在下一帧边界验证物理帧格式后提交最后一个采样字节，避免发布少行或少像素图像。

两个缓存银行分别经历空闲、写入、可读和读取状态。CPU 取得完整图像的读取所有权后，图像在释放前不会被新帧覆盖。两个缓存均繁忙时丢弃新帧并统计，不反压连续视频。96×54 数据上下补零，逻辑上提供 96×96、每行 96 字节的 GRAY8 图像；补零区由读端生成。字节和 SUM32、帧号和采集时间用于 CPU 导出一致性核验。

该版本验证了单时钟接口；实际 CPU 与视频跨域需要请求/响应和快照适配。当前并未分配硬件寄存器地址。模型 INT8 量化和采样方式的识别准确率应在真实模型与数据上进一步核验，不能仅由缓存校验推出。

## 显示与网络

显示模块统一延迟 RGB 与行场/有效控制一拍，在场边界锁存标量状态。它支持单独的 32×24 热图面板、温湿度数字、AI 与融合分值、事件类型码、报警红框及外部预测点。无效量显示缺失标记；AI 与预测坐标检查结果帧号，避免画在不对应的视频帧上。热图前台缓存及传感器温度换算由其他子系统提供。显示预测点并不表示本模块具有跟踪预测算法。

PC 接收器基于 UDP，最大载荷 1200 字节，96×96 图像分成 8 个包。协议通过 session/事件/帧编号关联数据，验证整消息与分片报头/载荷 CRC32，处理乱序、重复、缺片超时和容量上限。只有完整图像才保存与展示。程序同时记录原始数据、JSONL、CSV 和图像，测试生成的数据明确标记 SYNTHETIC；网络数据标记待核验，须结合板端及现场记录认定来源。

## 已完成的验证

1. Python 侧 15 项测试，覆盖真实本机 UDP 回环、网页接口、图像落盘、60 次随机分片顺序、重复/超时/冲突/CRC、会话隔离、2000 个随机异常报文，以及采集日志与缓存文件核验，全部通过。
2. 缓存测试完成 54,777 次时钟观察，覆盖整图读取、双缓存顺序、繁忙丢新帧、早 EOF、缺 EOF、abort、新 SOF 恢复和无所有权/越界读取。
3. 小尺寸采集测试验证完整/坏帧及最后采样字节的元数据归属；显示测试验证 3 帧、260,286 个周期，包含状态、温湿度/分值文字、热图、报警、预测点和帧号不匹配的抑制。
4. 完整采集→缓存链路输入两帧 1920×1080，共 4,147,200 个像素，产生 10,368 个网格采样，CPU 读取 18,432 字节；两张 96×96 图像的内容、填充、校验及元数据全部匹配。
5. A 独立模块由 Efinity 2026.1.132 对 Ti60F225 I3 综合通过，报告 2,283 LUT、1,078 FF、16 RAM10 和 2 DSP。此结果未包含实际 CPU、DDR、CSI/HDMI 与热图存储，也未执行布局布线与最终时序签核；不能直接当作整机资源。
6. 提供给集成方的 C 读取/分片接口按 RV32IM、ILP32 交叉编译通过；尚无实际 CPU 执行证据。
