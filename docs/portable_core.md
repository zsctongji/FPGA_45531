# 视觉预处理 RTL 子模块

这部分可作为 Ti60F225 多模态终端的视觉预处理基础。它只处理已进入 FPGA 的 RGB 像素流；摄像头采集、显示接口、存储器、语音采集、AI 推理和板级工程仍需接入。文件没有厂家 IP、引脚分配或猜测的时钟约束。

## 文件与算法

| 文件 | 功能 |
|---|---|
| `rtl/rgb888_to_gray.v` | `gray = (77×R + 150×G + 29×B + 128) >> 8`，带四舍五入 |
| `rtl/gray_threshold.v` | `gray >= THRESHOLD` 输出 255，否则输出 0；默认阈值 128 |
| `rtl/sobel_stream.v` | 3×3 Sobel，输出 `min(255, abs(Gx)+abs(Gy))` 及二值边缘；默认边缘阈值 80 |
| `rtl/portable_vision_core.v` | 连接以上三个模块，分别输出灰度、分割和边缘流 |

所有像素值都是无符号 8 位。两个阈值参数的合法范围是 0～255，比较包含等号。Sobel 核为：

```text
Gx = [-1  0  1]       Gy = [-1 -2 -1]
     [-2  0  2]            [ 0  0  0]
     [-1  0  1]            [ 1  2  1]
```

## 输入协议

- 单时钟 `clk`，低有效异步复位 `rst_n`。板级复位需要在解除时同步到 `clk`。
- 每个上升沿若 `in_valid=1`，接受一个 RGB888 像素。支持连续输入及任意数量的无效时钟间隔。没有 `ready`，下游必须能够接收每个有效输出。
- 像素按从左到右、从上到下排列。`WIDTH`、`HEIGHT` 是有效像素尺寸，均必须至少为 3；默认 640×480。
- `in_sof` 与每帧第一个有效像素一起为 1；`in_sol` 与每行第一个有效像素一起为 1；`in_eol` 与每行最后一个有效像素一起为 1；`in_eof` 与每帧最后一个有效像素一起为 1。标记随像素发送，不是空白区同步脉冲。
- `in_valid=0` 时输入数据和标记被忽略。复位或重新发送 `in_sof` 可开始新帧；重新开始后必须提供完整的前两行。

灰度和分割模块传递这四个标记。Sobel 根据 `WIDTH`/`HEIGHT` 和 `in_sof` 计数、重建自己的标记，因此输入每行必须恰好有 `WIDTH` 个有效像素，每帧必须恰好有 `HEIGHT` 行。它不检查错误的行长，也不接收 `in_sol/eol/eof`。

## 输出位置与延迟

输入 RGB 在第 N 个上升沿采样后，灰度及 `gray_*` 标记在该上升沿后可用；分割像素及 `binary_*` 标记在第 N+1 个上升沿后可用。对应 RTL 结构分别经过一个、两个寄存级。

当第 N 个上升沿接受输入坐标 `(x,y)`，且 `x>=2 && y>=2` 时，第 N+1 个上升沿后的边缘输出对应原图中心 `(x-1,y-1)`。Sobel 只输出内部区域，舍弃四周一圈像素，输出尺寸是 `(WIDTH-2)×(HEIGHT-2)`。例如 640×480 输入产生 638×478 边缘图。边缘行首对应输入 `x=2`，行尾对应 `x=WIDTH-1`；首帧标记对应输入 `(2,2)`，末帧标记对应输入 `(WIDTH-1,HEIGHT-1)`。

输出数据只在对应 `*_valid=1` 时有意义；无效周期的像素寄存器保留旧值，所有输出标记为 0。有效输入中的停顿不会改变行列位置。三种输出的帧大小和位置不同，接入显示接口时必须分别匹配尺寸、标记及数据，不能直接复用原摄像头同步信号。

## 存储与板级接入限制

Sobel 使用两个 8 位行缓冲，共 `2×WIDTH` 字节，并使用组合读取。缓冲不复位，在每帧前两行填充完成之前不输出。这个写法使用通用可综合 Verilog 结构；具体会映射到 LUT、寄存器还是 RAM，需要查看 Efinity 综合报告。它没有承诺 Ti60F225 的时钟频率或资源占用。若实际像素时钟较高，可在厂家工程中改为同步 RAM、增加寄存级，并重新验证标记延迟。

还需用真实开发板资料确定摄像头型号/数据格式、像素时钟、复位、电压、管脚、显示或传输方式。若摄像头不是 RGB888，需先加入数据解包和格式转换。当前文件不能生成可直接烧录 Ti60F225 的配置文件。

## 自检方法

`sim/tb_pixel_ops.sv` 使用整数乘除参考值检查灰度，不调用 DUT 输出作参考；同时验证阈值 0、127、128、255，包括等于阈值的像素。它检查 RGB 原色遍历、完整灰度遍历、随机颜色、随机有效停顿、无效周期中的假标记，以及流水中途复位。

`sim/tb_vision_stream.sv` 使用完整帧数组进行独立 2D 卷积参考计算，检查 8 帧 9×7 图像，包括黑色、白色、渐变、块棋盘、中心脉冲、颜色渐变和随机图。它检查连续帧、边界裁剪、重建帧/行标记、随机有效停顿、中途复位后的旧行存储恢复，以及 0、中间值、255 饱和输出。

`sim/tb_sobel_3x3.sv` 验证最小 3×3 输入的连续两帧，每帧恰好输出一个内部像素，并在该像素上同时设置帧首、行首、行尾、帧尾标记；同时检查饱和和边缘阈值 255 的等号。

`sim/tb_sobel_720p.sv` 验证两帧 1280×720 完整像素流，第一帧竖向阶跃，第二帧横向阶跃。使用阶跃图的解析梯度参考，检查全部灰度、分割和内部 Sobel 像素及标记，包含少量有效停顿。这个测试是 RTL 功能仿真，不能视为开发板 720p30 运行结果。

已实际通过 Vivado XSim 2018.3 和项目内 Icarus 两套仿真后端。两帧 720p 测试检查灰度、二值化各 1,843,200 点及 Sobel 1,835,208 点。受限环境曾发生 DLL 启动错误；在正常运行环境中已通过，不需要重装 Vivado。原始失败记录和成功记录均保留。功能仿真不代表已经在 Ti60F225 上完成综合、布线、时序收敛或硬件测试。
